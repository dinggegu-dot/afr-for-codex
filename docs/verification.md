# 验收与回滚

## 在空库验证

1. 安装后，设置独立的收件箱和 Obsidian 库。打开该库。
2. 放入一份 [合成示例](../examples/城市积水预警.md)。请求 AFR 收录。确认它取得固定版本，且尚未授权时，生成白板和读取原文的请求被拦截。
3. 逐份同意 Codex 研读。查询状态直到签发。打开白板和完整阅读，核对卡片能独立读懂，连线有含义，引用能回到固定段落。
4. 加入并授权 [第二份合成示例](../examples/社区演练评估.md)。请求以两份材料梳理共同问题。核对候选与两篇出处，确认其中一个入库，再从 Codex 追问两份材料的证据与差异。
5. 撤回其中一个版本授权。再次查询原文，确认权限已生效，检查此前产物仍保留在本地。
6. 如需测试持续收录，以默认仅本机收录的模式开启监听。放入一份新样例，查询它是否收录且仍未授权，然后关闭监听。

## 停用与恢复

- 先在 Codex 中发送「关闭 AFR 收件箱监听」。如果启用了讨论写入，可另行要求关闭。
- 如有任务仍在运行，先用 AFR 查看状态和具体文章授权，再在 Codex 的 **Plugins** 页面停用或卸载 AFR for Codex。
- 收件箱、Obsidian 库和对应状态可作为同一份本机备份保留。插件的版本回滚可用对应 Git 标签重新添加目录。恢复时使用同一套归档及插件状态，再核对授权和监听设置。

如遇 `user_edit_conflict`，先备份和核对问题笔记的生成区，再用同一个候选重新确认。手写内容可放在生成区之外。

## 开发者复验

在依赖已安装的 Python 3.11 环境下运行无模型回归。

```bash
PYTHONPATH=plugins/afr-for-codex/runtime python -B -m unittest discover -s test -v
```

## 0.1.0 校验记录

| 验收项 | 实测结果 |
| --- | --- |
| macOS Apple Silicon 安装 | 空 Codex 配置安装，App Server 识别 AFR Skill、本机 MCP 和 20 个工具。在测试目录调用 `afr_status` 成功 |
| 真实 Codex 研读 | 两份合成研报均按主题签发白板和完整阅读，能由话题链接回到固定原文 |
| 研究问题 | 真实跨篇校读生成两个候选。在空库选择候选入库回读，材料来源齐全，重复确认保持同一版本 |
| 权限限制 | 未授权的原文无法读取或发起研读。撤回后阻止读取该版本及依赖它的问题，本机白板仍在 |
| 本机自动收录 | 独立的 macOS 登录会话后台任务收录合成材料，模型调用为零。停止后确认该任务已移除 |
| 自动化回归 | 16 项通过，包括 Word 和 PDF 固定定位、白板排布、授权、入库及后台任务失败恢复 |

测试资料为仓库里的合成示例。实际安装验证使用 Codex CLI 和 App Server。本次平台覆盖 macOS Apple Silicon。
